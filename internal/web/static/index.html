SPL Quick Reference

1. Start with the mental model

SPL is essentially: search → filter → transform → aggregate → visualize

index=security sourcetype=auth
| where status="failed"
| stats count by user
| sort -count

Read it as: Find authentication events → keep failures → count them per user → sort by frequency. The | is the key concept — each command receives the results from the previous command.

2. Learn these commands first

Don't try to learn all of SPL. These will get you surprisingly far:

CommandPurpose
searchFind events
whereFilter using expressions
fieldsSelect/remove fields
tableDisplay specific fields
renameRename fields
evalCreate/modify fields
statsAggregate data
timechartTime-based aggregation
sortSort results
dedupRemove duplicates
rexExtract fields with regex
lookupEnrich events
eventstatsAdd aggregate statistics to events
streamstatsRunning/windowed statistics
binBucket values, especially time
joinCombine datasets — learn it

Focus on: search, where, eval, stats, timechart, rex, lookup.

3. Learn stats extremely well

This is probably the single most important SPL command.

index=web
| stats count by status

Output conceptually:

status    count
200       15432
404       821
500       93
index=web
| stats count avg(response_time) max(response_time) by endpoint
index=web
| stats
    count as requests
    avg(response_time) as avg_latency
    max(response_time) as max_latency
  by endpoint

Once you understand stats, you're already quite far into SIEM-style querying.

4. Then learn eval
index=web
| eval duration_ms=duration*1000
| eval slow=if(duration_ms > 1000, "yes", "no")
| stats count by slow

You can think of eval somewhat like:

SELECT
    ...,
    duration * 1000 AS duration_ms

...but SPL's expression language has its own functions.

5. Learn time-series queries

This becomes extremely important for a SIEM.

index=security
| timechart count by severity
index=security
| timechart span=5m count
index=security
| timechart span=1h count by source_ip

This is where SPL starts becoming particularly useful for security analytics.

6. Learn field extraction

Real logs aren't always nicely structured:

Failed login from 192.168.1.50 for user mauro

You can use:

| rex "from (?<src_ip>\d+\.\d+\.\d+\.\d+)"

Now you have: src_ip = 192.168.1.50. This is very relevant to Quetzalog, because you'll likely want your ingestion layer to normalize different log formats into fields that SPL queries can operate on.

7. Practice with security questions

Rather than doing generic SPL exercises, learn it through actual SIEM questions:

Top attacking IPs

index=security
| stats count by src_ip
| sort -count
| head 20

Failed logins by user

index=auth action=failed
| stats count by user
| sort -count

Brute-force candidates

index=auth action=failed
| stats count as failures by src_ip
| where failures > 20

Successful login after many failures — exactly the kind of query you should work toward:

index=auth
| sort 0 src_ip _time
| streamstats count(eval(action="failed")) as failures by src_ip
| where action="success" AND failures > 10
